## 一、功能概述

本次实现基于 **LangGraph Checkpoint** 的短期记忆增强功能，使智能体能够：
- 在多轮对话中保持上下文连贯性
- 通过 `thread_id` 恢复对话状态
- 支持指代消解（理解"这些"、"那部"等）
- 断点恢复（服务重启后可继续对话，需 Redis）

---

## 二、技术原理

### 2.1 LangGraph Checkpoint 机制

LangGraph Checkpoint 是 LangGraph 框架提供的**状态持久化**机制，核心原理如下：

```
用户请求（thread_id="user-123"）
    ↓
LangGraph 引擎检查 Checkpoint
    ↓
找到上次状态 → 恢复 AgentState
    ↓
执行节点（意图解析 → 计划生成 → 工具执行 → 响应生成）
    ↓
每个节点转换后 → 自动保存状态快照
    ↓
返回响应
```

### 2.2 状态快照内容

每次 Checkpoint 保存的 `AgentState` 包含：

```python
class AgentState(TypedDict):
    messages: list                    # 消息历史
    user_query: str                   # 用户查询
    intent_type: str                  # 意图类型
    response_mode: str                # 响应模式
    intent: dict                      # 解析后的意图
    query_params: dict                # 查询参数
    anime_results: list[dict]         # 番剧数据
    final_response: str               # 最终回复
    needs_data_fetch: bool            # 是否需要获取数据
    cache_hit: bool                   # 是否命中缓存
```

### 2.3 Thread ID 机制

`thread_id` 是**对话线程的唯一标识符**：

- 同一个 `thread_id` → 同一个对话会话
- 不同 `thread_id` → 不同的对话会话
- 每次请求传入相同的 `thread_id`，LangGraph 自动恢复上次的状态

## 三、两种 Checkpointer 对比

### 3.1 内存版 Checkpointer（InMemorySaver）

**特点**：
- 存储在进程内存中
- 速度快，无需额外依赖
- **进程重启后状态丢失**
- 单实例使用

**适用场景**：
- ✅ 开发/测试环境
- ✅ 个人项目
- ✅ 单实例部署
- ❌ 生产环境（需要持久化）

**代码示例**：
```python
from langgraph.checkpoint.memory import InMemorySaver

checkpointer = InMemorySaver()
graph = graph.compile(checkpointer=checkpointer)
```

### 3.2 Redis 版 Checkpointer（RedisSaver）

**特点**：
- 存储在 Redis 中
- **跨进程共享状态**
- **服务重启后状态保留**
- 支持多实例部署

**适用场景**：
- ✅ 生产环境
- ✅ 多实例部署
- ✅ 需要断点恢复
- ✅ 高可用架构

**代码示例**：
```python
from langgraph.checkpoint.redis import RedisSaver

checkpointer = RedisSaver.from_url(
    "redis://localhost:6379",
    key_prefix="langgraph:"
)
graph = graph.compile(checkpointer=checkpointer)
```

### 3.3 详细对比表

| 特性 | 内存版 | Redis 版 |
|------|--------|----------|
| **存储位置** | 进程内存 | Redis 服务器 |
| **持久化** | ❌ 进程重启后丢失 | ✅ 持久化 |
| **跨进程共享** | ❌ 不支持 | ✅ 支持 |
| **多实例部署** | ❌ 不支持 | ✅ 支持 |
| **断点恢复** | ❌ 不支持 | ✅ 支持 |
| **访问速度** | 极快（内存） | 快（Redis） |
| **额外依赖** | 无 | Redis 服务器 |
| **安装命令** | 内置 | `pip install langgraph-checkpoint-redis` |
| **配置复杂度** | 低 | 中 |
| **适用环境** | 开发/测试 | 生产环境 |

### 4.2 自动选择机制

项目根据配置自动选择 Checkpointer：

```python
def create_checkpoint_agent_graph() -> StateGraph:
    """创建带 Checkpoint 的 Agent 图（使用默认配置）"""
    config = get_checkpoint_config()
    
    if config.backend == "redis":
        # 尝试使用 Redis
        try:
            redis_checkpointer = get_redis_checkpointer()
            checkpointer = redis_checkpointer.saver
        except Exception as e:
            logger.warning(f"Redis Checkpoint 初始化失败: {e}，回退到内存存储")
            checkpointer = get_memory_saver()
    else:
        # 使用内存存储
        checkpointer = get_memory_saver()
    
    return create_agent_graph(checkpointer)
```

## 五、使用方法

### 5.1 API 调用方式

#### 第一次请求（无 thread_id）

```bash
curl -X POST http://localhost:8000/api/chat/stream \
  -H "Content-Type: application/json" \
  -d '{
    "query": "推荐几部日漫",
    "user_id": "user-123"
  }'
```

**响应示例**：
```json
{
  "type": "session",
  "session_id": "abc-123",
  "trace_id": "trace-456",
  "thread_id": "abc-123"
}
```

#### 后续请求（传入 thread_id）

```bash
curl -X POST http://localhost:8000/api/chat/stream \
  -H "Content-Type: application/json" \
  -d '{
    "query": "这些番剧的评分是多少",
    "thread_id": "abc-123"
  }'
```

**智能体理解**：
- "这些" → 指代上一次查询的日漫
- "评分是多少" → 获取这些番剧的评分

### 5.2 代码调用方式

```python
from src.agent.agent import get_agent

# 启用 Checkpoint 的 Agent
agent = get_agent(enable_checkpoint=True)

# 第一次对话
async for chunk in agent.run_streaming(
    "推荐几部日漫", 
    thread_id="user-123"
):
    print(chunk)

# 第二次对话（自动恢复状态）
async for chunk in agent.run_streaming(
    "这些的评分呢",  # "这些" 指代上次的日漫
    thread_id="user-123"  # 相同的 thread_id
):
    print(chunk)
```

### 5.3 SessionManager vs Checkpoint

两种方案可以同时使用：

| 特性 | SessionManager | LangGraph Checkpoint |
|------|---------------|---------------------|
| **用途** | 会话消息管理 | 图状态持久化 |
| **存储内容** | 对话历史 | 完整 AgentState |
| **恢复能力** | 部分恢复 | 完整恢复断点 |
| **配置复杂度** | 低 | 中 |
| **推荐使用** | 消息历史查询 | 多轮对话状态 |

## 六、配置说明

## 七、生产环境部署建议

### 7.1 是否需要安装 Redis 版 Checkpointer？

**决策树**：

```
是否需要服务重启后保留对话状态？
├─ 否 → 使用内存版（当前配置，无需安装）
└─ 是 → 是否需要多实例部署？
    ├─ 否 → 仍可使用内存版
    └─ 是 → 必须安装 Redis 版
```

### 7.2 安装 Redis 版 Checkpointer

**步骤 1**：安装依赖
```bash
pip install langgraph-checkpoint-redis
```

**步骤 2**：配置 Redis 连接
```bash
# 修改 .env 文件
CHECKPOINT_BACKEND=redis
REDIS_URL=redis://localhost:6379
```

**步骤 3**：启动 Redis 服务
```bash
# Windows（使用 WSL 或 Docker）
docker run -d -p 6379:6379 redis:latest

# 或使用本地 Redis 服务器
redis-server
```

**步骤 4**：重启应用
```bash
# 应用会自动检测到 Redis 并切换到 Redis 版 Checkpointer
```

### 7.3 Redis 性能优化

```python
# 配置连接池
```

## 八、常见问题

### Q1: 当前使用内存版，有什么限制？

**A**: 
- ✅ 多轮对话功能正常
- ✅ 指代消解正常工作
- ⚠️ 服务重启后对话状态丢失
- ⚠️ 不能跨实例共享状态

**影响评估**：
- 开发/测试：无影响
- 生产环境（单实例）：影响较小
- 生产环境（多实例）：必须升级到 Redis

### Q2: 如何验证 Checkpoint 是否正常工作？

**A**: 检查日志输出：

```bash
# 内存版
✅ 使用内存 Checkpoint 存储

# Redis 版
✅ 使用 Redis Checkpoint 存储: redis://localhost:6379
```

### Q3: thread_id 和 session_id 的区别？

**A**:
- `thread_id`：LangGraph Checkpoint 的线程标识
- `session_id`：SessionManager 的会话标识
- 两者可以相同，也可以不同
- 推荐使用相同的值，便于管理

### Q4: 如何清理旧的 Checkpoint 数据？

**A**:

**内存版**：
```python
# 重启服务即可清空
```

**Redis 版**：
```bash
# 通过 Redis CLI
redis-cli
> KEYS langgraph:*
> DEL langgraph:thread-1

# 或使用 TTL 自动过期
```

### Q5: Checkpoint 会存储多久？

**A**:
- 内存版：进程生命周期
- Redis 版：根据 `CHECKPOINT_TTL` 配置（默认 24 小时）
