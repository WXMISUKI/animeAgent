# 番剧智能体意图识别修改方案

## 一、当前问题诊断

### 1.1 问题现状

根据对项目代码和日志的分析，当前意图解析模块主要存在以下问题：

**参数提取不稳定**：当用户输入包含“国漫”、“日漫”、“剧场版”等关键词时，LLM有时无法正确提取anime_type参数，返回空字典{}或默认值all。这表明当前的prompt设计对LLM的引导不够有效。

**缺乏Few-Shot示例**：当前prompt仅包含规则描述，没有提供正反例样本。LLM对复杂规则的理解依赖其自身能力，容易出现理解偏差。

**缺少结构化输出校验**：虽然prompt要求输出JSON格式，但缺乏强制性的格式约束，导致输出的JSON可能不符合预期结构。

**意图分类较粗**：当前只有GREETING、CAPABILITY、QUERY、DETAIL、RANKING等少数意图类别，无法处理更细粒度的用户需求。

### 1.2 问题根因分析

根据业界实践，当前方案属于“初级方案A”（纯prompt工程驱动），存在以下固有缺陷：

**prompt膨胀风险**：当意图类型和参数规则增加时，prompt长度会大幅膨胀，导致LLM处理负担加重，容易出现意图混淆。

**泛化能力不足**：纯依赖LLM的实时泛化能力，对于方言、口语化表达、特异句式的理解能力有限。

**缺乏容错机制**：没有在LLM输出后进行格式校验和纠正，JSON解析失败时直接返回空字典。

## 二、成熟智能体意图识别方案分析

根据对业界实践的研究，成熟的意图识别方案分为四个阶段：

### 2.1 方案A：提示词工程驱动（初级）

通过精细化prompt设计，在单一LLM节点中同时实现意图识别和槽位抽取。核心包括：意图和槽位明确定义、Few-Shot示例引导、结构化输出约束。

**适用场景**：意图分支少（≤5个）、业务场景简单

**当前项目状态**：基本处于这个阶段，但Few-Shot和结构化输出约束不够完善

### 2.2 方案B：意图与抽槽节点分离（中级）

将意图识别和槽位抽取拆分为两个独立LLM节点。意图识别节点仅判断意图类别，槽位抽取节点为每个意图配置专属规则。

**适用场景**：意图分支多（5-15个）、业务逻辑复杂

**优点**：架构清晰，维护性强；提示词长度可控

**缺点**：系统调用次数增加，延迟升高

### 2.3 方案C：前置意图RAG召回（进阶）

构建“意图泛化知识库”，将LLM的实时泛化转化为预泛化。用户提问时，先通过RAG检索召回最相似的泛化示例，再提交给LLM。

**适用场景**：单轮对话为主、存在大量特异表达

**优点**：泛化能力可控，Bad Case修复快；可选用性价比更高的模型

### 2.4 方案D：合并节点+升级RAG（高阶）

在方案C基础上，增加多轮对话理解和直接回答机制。构建包含【历史提问】【最新提问】【思考过程】【意图】【槽位】的完整Case库。

**适用场景**：多轮对话为主、实时性要求高、准确率要求严格

**优点**：多轮理解能力强，准确率达97.6%；延迟可控

## 三、修改方案设计

### 3.1 总体策略

鉴于当前项目实际情况，建议采用**渐进式改进**策略：

**第一阶段（短期）**：完善初级方案A，增加Few-Shot示例和结构化输出约束

**第二阶段（中期）**：引入方案B的思想，将意图识别与参数提取分离

**第三阶段（长期）**：根据业务复杂度演进到方案C或方案D

### 3.2 第一阶段修改：增强型Prompt Engineering

#### 3.2.1 增加Few-Shot示例

#### 3.2.2 增加结构化输出约束

使用Pydantic或JSON Schema约束输出格式，并在代码层面增加强制校验。

```python
from pydantic import BaseModel, Field
from typing import Optional, Literal

class IntentParams(BaseModel):
    """意图参数结构化定义"""
    time_range: Optional[str] = Field(default="", description="时间范围")
    platform: Optional[str] = Field(default="all", description="平台选择")
    anime_type: str = Field(default="all", description="番剧类型")
    sort_by: str = Field(default="rating", description="排序方式")
    keyword: Optional[str] = Field(default="", description="关键词搜索")

    # 添加验证器
    def validate_and_correct(self) -> "IntentParams":
        # 枚举值校验
        valid_platforms = ["jikan", "anilist", "bangumi", "bilibili", "all"]
        valid_types = ["日漫", "国漫", "剧场版", "OVA", "all"]
        valid_sorts = ["rating", "hot", "latest"]
        
        if self.platform not in valid_platforms:
            self.platform = "all"
        if self.anime_type not in valid_types:
            self.anime_type = "all"
        if self.sort_by not in valid_sorts:
            self.sort_by = "rating"
            
        return self
```

#### 3.2.3 增加规则兜底机制

在LLM提取失败时，使用基于关键词的规则匹配作为兜底。

```python
def _rule_based_extract(user_input: str) -> dict:
    """基于规则的参数提取（兜底方案）"""
    params = {
        "anime_type": "all",
        "time_range": "",
        "platform": "all",
        "sort_by": "rating",
        "keyword": ""
    }
    
    # 检测番剧类型关键词
    if any(kw in user_input for kw in ["国漫", "国产", "国创"]):
        params["anime_type"] = "国漫"
    elif any(kw in user_input for kw in ["日漫", "日本动画"]):
        params["anime_type"] = "日漫"
    elif any(kw in user_input for kw in ["剧场版", "电影版", "电影"]):
        params["anime_type"] = "剧场版"
    elif any(kw in user_input for kw in ["OVA"]):
        params["anime_type"] = "OVA"
    
    # 检测时间范围关键词
    import re
    time_patterns = [
        (r"(\d{4})年(\d{1,2})月", lambda m: f"{m.group(1)}-{int(m.group(2)):02d}"),
        (r"(\d{4})-(\d{2})", lambda m: f"{m.group(1)}-{m.group(2)}"),
        (r"本月|这个月", lambda m: "本月"),
        (r"最新|最近|新番", lambda m: "最新"),
        (r"春季|春番", lambda m: "春"),
        (r"夏季|夏番", lambda m: "夏"),
        (r"秋季|秋番", lambda m: "秋"),
        (r"冬季|冬番", lambda m: "冬"),
    ]
    
    for pattern, extractor in time_patterns:
        match = re.search(pattern, user_input)
        if match:
            params["time_range"] = extractor(match)
            break
    
    # 检测排序关键词
    if any(kw in user_input for kw in ["最热", "热门", "火", "热度"]):
        params["sort_by"] = "hot"
    elif any(kw in user_input for kw in ["最新", "新番", "最近"]):
        params["sort_by"] = "latest"
    elif any(kw in user_input for kw in ["评分", "高分", "推荐"]):
        params["sort_by"] = "rating"
    
    return params
```

## 七、总结

本次修改方案基于业界成熟的意图识别最佳实践，结合项目当前实际情况，提出了渐进式的改进路径。

**核心改进点**：

1. **增加Few-Shot示例**：让LLM更好地理解参数提取规则

2. **规则兜底机制**：确保即使LLM失败也能返回合理结果

3. **参数校验纠正**：防止非法值影响后续流程

4. **意图与参数分离**：架构更清晰，便于针对性优化

5. **配置化管理**：prompt和规则可配置，易于调整

通过这些改进，预计可以将参数提取成功率从当前的约60%提升到90%以上，为用户提供更稳定、更智能的服务体验。
