# 番剧智能体项目技术文档

## 项目概述

**番剧智能体** 是一个基于 LangGraph + LangChain + MiniMax M2.5 的企业级智能问答系统，专注于番剧信息查询与推荐。项目采用 ReAct（Reasoning + Acting）架构模式，实现了多轮对话、多数据源并行查询、流式输出、监控追踪等企业级特性。

### 项目定位
- **垂直领域**：番剧（动漫）信息智能查询与推荐
- **技术架构**：基于 LangGraph 状态机的 ReAct Agent
- **部署形态**：FastAPI 后端服务 + Web 前端界面
- **核心能力**：意图识别、参数解析、工具执行、响应生成、多轮对话

## 核心功能

### 1. 智能意图识别系统
支持 **11 种意图类型**的精准识别：

| 意图类型 | 说明 | 示例 |
|----------|------|------|
| `query` | 番剧查询 | "2026年4月有什么新番？" |
| `detail` | 番剧详情 | "介绍一下葬送的芙莉莲" |
| `ranking` | 排行榜 | "现在最火的番剧有哪些？" |
| `recommend` | 推荐 | "给我推荐几部治愈番" |
| `compare` | 对比 | "鬼灭之刃和咒术回战哪个好看？" |
| `greeting` | 打招呼 | "你好" |
| `description` | 询问身份 | "你是谁？" |
| `capability` | 询问能力 | "你能做什么？" |
| `thanks` | 感谢 | "谢谢" |
| `chat` | 闲聊 | "今天天气怎么样？" |
| `unknown` | 无法理解 | 其他模糊查询 |

**技术实现**：
- 基于 LLM 的意图分类（`classify_intent` 节点）
- 针对每种意图类型设计专用的 Prompt 模板
- 支持 5 种参数提取模式：`time_range`、`keyword`、`platform`、`genre`、`ranking_type`

### 2. 多轮对话与短期记忆
基于 **LangGraph Checkpoint** 实现状态持久化：

- **记忆能力**：记住前几轮对话的上下文，支持追问和指代消解
- **状态管理**：自动保存用户查询、意图解析结果、工具执行历史
- **存储后端**：
  - 内存存储（开发/测试环境）
  - Redis 存储（生产环境，支持分布式）
- **使用方式**：通过 `thread_id` 参数恢复对话状态

**典型场景**：
```
用户：2026年4月有什么新番？
智能体：根据查询，2026年4月有以下新番...

用户：那5月呢？
智能体：根据查询，2026年5月有以下新番...
      （智能体记住用户在询问番剧，自动推断为"2026年5月的新番"）
```

### 3. 多数据源并行查询
实现 **数据源路由器**，支持多数据源并行查询和自动 Fallback：

**数据源策略**：
- 优先级：Jikan API > AniList API > Bangumi API > Bilibili API
- 并行查询：同时调用多个数据源，取最快返回的结果
- Fallback 机制：所有数据源失败时，自动调用百度搜索

**代码实现**：
```python
PLATFORM_MAP = {
    "jikan": ["Jikan"],
    "anilist": ["AniList"],
    "bangumi": ["Bangumi"],
    "all": ["Jikan", "AniList"],  # 并行查询
}
```

### 4. 流式输出实时响应
采用 **Server-Sent Events (SSE)** 实现增量输出：

**流式响应格式**：
1. **会话信息**：返回 `session_id`、`trace_id`、`thread_id`
2. **意图解析**：实时显示识别到的意图和提取的参数
3. **执行计划**：显示将要执行的工具列表
4. **工具执行**：显示每个工具的执行结果
5. **增量输出**：逐字输出 LLM 生成的回复内容
6. **完成信号**：发送 `done` 事件

**用户体验**：
- 打字机效果，提升交互体验
- 实时反馈每个执行步骤，增强透明度
- 支持长时间对话，避免超时

### 5. 企业级监控与追踪
完整的 **Prometheus 监控指标**和**分布式链路追踪**：

#### 监控指标（Prometheus 兼容）
| 指标名称 | 类型 | 说明 |
|----------|------|------|
| `anime_agent_requests_total` | Counter | 请求总数 |
| `anime_agent_errors_total` | Counter | 错误总数 |
| `anime_agent_request_duration_seconds` | Histogram | 请求耗时分布 |
| `anime_agent_intent_parse_duration_seconds` | Histogram | 意图解析耗时 |
| `anime_agent_data_source_duration_seconds` | Histogram | 数据源响应时间 |
| `anime_agent_cache_hit_ratio` | Gauge | 缓存命中率 |

**访问方式**：
```bash
GET /metrics
```

#### 链路追踪
每个请求生成唯一的 `trace_id`，记录完整请求链路：
- 用户查询内容
- 意图解析结果
- 参数提取结果
- 工具调用过程
- 数据源查询时间
- 最终响应内容

**日志示例**：
```
📥 收到请求 | Trace: trace_abc123 | 用户: 2026年4月有什么新番？
🎯 意图解析完成: query | 参数: {"time_range": "2026-04"}
📋 执行计划完成: ["query_anime"]
⚡ 工具执行完成: 2/2 成功 | Trace: trace_abc123
✅ 对话完成 | 共发送 15 个chunk | Trace: trace_abc123
```

### 6. 完善的异常处理体系
定义 **6 种自定义异常类型**，实现精细化错误处理：

| 异常类型 | 说明 | HTTP 状态码 |
|----------|------|-------------|
| `AnimeAgentException` | 智能体基础异常 | 500 |
| `DataSourceException` | 数据源异常 | 503 |
| `IntentParseException` | 意图解析异常 | 400 |
| `ToolExecutionException` | 工具执行异常 | 500 |
| `SessionException` | 会话管理异常 | 500 |
| `ValidationException` | 参数验证异常 | 400 |

**错误处理策略**：
- 全局异常捕获，统一返回格式
- 用户友好的错误消息转换
- 详细的错误日志记录
- 流式响应中的错误隔离（单个步骤失败不影响整体流程）

### LangGraph 状态机流程

```
用户输入
    │
    ▼
┌──────────────┐
│classify_intent│ 意图分类（11种意图类型）
└──────┬───────┘
       │
       ├─→ direct_reply → 直接回复（打招呼等）
       │
       └─→ parse_intent → 参数解析
              │
              ▼
         execute_skill → 工具执行
              │
              ▼
         format_response → 响应生成
              │
              ▼
         最终回复
```

## 技术亮点

### 1. 基于 LangGraph 的状态机架构
- 采用 **ReAct 模式**，实现"推理-行动"循环
- 支持 **Checkpoint 机制**，实现多轮对话状态持久化
- 模块化节点设计，易于扩展和维护

### 2. 企业级多数据源架构
- **并行查询**：同时调用多个数据源，取最快返回的结果
- **自动 Fallback**：数据源失败时自动降级到百度搜索
- **统一接口**：通过路由器屏蔽数据源差异

### 3. 完整的监控体系
- **Prometheus 兼容**：支持 Grafana 可视化
- **分布式追踪**：每个请求生成唯一 Trace ID
- **结构化日志**：使用 Loguru 记录关键事件

### 4. 高性能流式输出
- **SSE 协议**：实现增量输出和实时反馈
- **异步处理**：使用 `async/await` 提升并发性能
- **错误隔离**：单个步骤失败不影响整体流程

### 5. 完善的测试体系
- **单元测试**：覆盖意图识别、工具执行、数据源查询
- **集成测试**：测试多数据源并行查询和流式响应
- **异步测试**：使用 `pytest-asyncio` 测试异步代码

## 部署说明

### 环境要求
- Python 3.10+
- Redis（可选，用于多轮对话状态持久化）
- MiniMax API Key（通过阿里云 DashScope 获取）

### 启动步骤

**1. 安装依赖**
```bash
pip install -r requirements.txt
```

**2. 配置环境变量**
```env
# MiniMax 配置
ORCH_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
ORCH_MODEL=MiniMax/MiniMax-M2.5
ORCH_API_KEY=sk-your-api-key-here

# Checkpoint 配置（可选）
CHECKPOINT_ENABLE=true
CHECKPOINT_BACKEND=redis
REDIS_URL=redis://localhost:6379/0
```

**3. 启动后端服务**
```bash
uvicorn src.main:app --reload --port 8000
```

**4. 启动前端服务**
```bash
cd frontend
python -m http.server 8080
```

**5. 访问应用**
- Web 界面：http://localhost:8080
- API 文档：http://localhost:8000/docs
- 监控指标：http://localhost:8000/metrics
